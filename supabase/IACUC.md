# IACUC records and permissions

Apply `iacuc.sql` after the schema, export, and manager migrations. It creates no protocol data, accounts, approvals, renewals, or documents. It adds the owner-controlled `iacuc` manager permission, typed validation for four husbandry event kinds, and the current bounded report projector. Existing managers receive the same enabled default as other newly added operational capabilities; an explicit owner denial is preserved on rerun. Editors/owners can write, viewers can read, and only the owner can change membership capabilities. Re-deploy `manage-colony-users` because its permission-key allowlist now includes `iacuc`. Changing a protocol reference on a mouse, cage, mating, litter, experiment or sample also requires IACUC permission; ordinary edits with unchanged references retain their normal section permissions.

Each event contains exactly one matching nested object: `iacuc_protocol`, `iacuc_assignment`, `iacuc_usage`, or `iacuc_design`, with `schema_version:1` and `protocol_id`. A protocol's `protocol_id` equals its event ID; other types reference that ID. Record dates use ISO calendar dates or null when unknown. Usage inner/outer dates must agree. Known expiry dates do not automatically mark an approval renewed or change its status.

Protocols hold approval metadata, separately identified species/strain allocations, the source URL/hash/filename, sanitized document text, and narrative sections. Document text is limited to 300,000 characters and the complete event to 1.5 MB. Source and document links must use HTTPS. Original PDFs remain private offline source files or behind the source portal login; there is no public file, public bucket or signed link in this feature. Remove contact details before importing text into the member-readable colony record. The record validator checks structure and limits, not the scientific meaning or completeness of redaction.

Assignments identify a mouse, cage, mating, litter or experiment plus purpose, validity dates and evidence status. Assignment alone is not a counted use or a completed experiment. Usage identifies `used` or `bred`, confirmed mouse IDs, a separate unregistered count and source evidence. Repeated mouse IDs within one event are rejected. Across events, reporting must deduplicate mice for each protocol/category and report unregistered aggregate counts separately; it must not sum repeated experiment appearances or cage occupancy to infer animals used.

Saved designs hold bounded `inputs`/`results` objects and optional `breeding_inputs`/`breeding_results`. Scalar counts and nested adjustment outputs are exportable through explicit allowlists. Stored planning results remain assumptions-based planning evidence, not protocol approval or an assurance of biological yield.

The existing Low three-year / High six-year / Max full-history export rules use the outer event date. Source access times, imports, edits and planning timestamps cannot make historical usage recent. Undated events require Max. Bounded reports exclude raw document text, narrative sections, notes and raw source references; safe allocation/usage/planning fields remain. Array projections have counts and truncation indicators where appropriate. Full preservation backups still require Max.

`supabase/tests/iacuc.test.mjs` covers typed validation, owner-only permission controls, nested/retyping bypasses, private source visibility, stale updates and batch rollback, duplicate usage IDs, report omission of narratives, and 3/6-year history limits. Run with `node --no-maglev --test supabase/tests/iacuc.test.mjs`; no live database or source PDF is used.
