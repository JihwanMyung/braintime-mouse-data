# Current Animal Sheet parser and merge

`source.mjs` reads only the explicitly configured `expectedSourceId` workbook, worksheet IDs `1717598677`, `495325388`, and `1250760483`. Fetch native Google Sheets `properties`, `merges`, and `data.rowData.values` including effective/user-entered values, number-format types, effective borders, notes and formulas. The endpoint retains the full native response privately. No XLSX library or browser-side credentials are required.

`parseAnimalSheetWorkbook(workbook, {capturedAt, dataset, managerDirectory, expectedSourceId})` is asynchronous. `dataset.tables.mice` is optional and supplies literal tag/SID candidates only. `managerDirectory` is an optional private list of `{code, name, aliases:[]}`; aliases must come from verified source/account evidence. It returns `{schema_version, parser_version, source_id, captured_at, snapshot_date, content_hash, records, issues, coverage}`. Each record has `{entity_type, entity_id, payload}`. The four record types are rooms, racks, locations and light_events. There are no animal or cage mutations.

Parser version 2 also retains unlabelled SPF cage grids. An empty merge is accepted only when it is one row by six columns, has a labelled SPF peer on the same row, and has a complete thick cage outline with five or six body rows. Missing borders, incomplete outlines, header notes/formulas, manager rows, and other formatted blank areas do not qualify. Generated labels such as `Unlabelled grid AT15` identify the source coordinate, not an invented cage name. These records carry `source_grid_basis: "border_verified_cage_grid"`, `source_grid_label_status: "unlabelled"`, and the exact `source_grid_boundary_range`; they use the same coordinate-derived ID that a later labelled position would use. Empty physical positions contribute to grid capacity without asserting animals are present. Existing source records remain unchanged; discoveries enter through the normal additive CAS/history merge. A later source label change still follows the existing position-identity review rule.

Physical position IDs and room/rack IDs match the original reconstruction. Manager cells are read only within the row immediately above each merged physical cage header. Generic labels are ignored; unmatched names and `GUEST` stay unresolved. Multiple people are ambiguous. The parser never fills a blank manager from neighboring cages. Source manager fields are `source_manager_raw`, `source_manager_name`, `source_manager_acronym`, `source_manager_status`, and `source_manager_evidence_refs`. Resolved means exact alias matching, not independent confirmation of responsibility.

`planAnimalSheetMerge(parsed, currentRecords, previousBaseline)` returns `{changes, conflicts, historyRecords, nextBaseline, summary}`. Current records require server versions. Changes carry `expected_version`; every commit must verify these atomically together with the import baseline revision. History envelopes use `husbandry_events`, `animal_sheet_source_change`, and `SHEET-HISTORY-*` IDs. Conflicts carry stable IDs, current/source/baseline payloads and exact source-managed keys.

A baseline is `{schema_version:1, source_id, content_hash, captured_at, entries:[{entity_type,entity_id,payload,source_present}]}`. Initial mismatches conflict. A verified original reconstruction may seed the first baseline through a private administrative initializer; the initializer must compare actual current rows against those originals. Source fields edited in the app are retained as conflicts. App-only fields survive ordinary source changes. Position identity changes require review.

Present empty positions clear only their baseline-owned source observations. Missing source positions remain in the database with `source_current:false`, their `source_last_seen_at`, and withdrawal history. They are not deleted or archived. Housing must label those source observations stale. Missing tabs, missing merged metadata, or a worksheet without supported positions fail parsing. A loss of more than 20% of at least five prior positions becomes review conflicts rather than a mass withdrawal.

A source observation timestamp is not an effective biological date. History records explicitly leave the effective date unknown. Animal identity, cage assignment and actual entrainment are never inferred. The raw hash excludes no source data; the endpoint must still run parsing/merge when the raw hash is unchanged because an updated exact-alias directory may change candidate resolution.

The caller must supply the source workbook ID from its private configuration. It must match the fetched workbook exactly. Stable position and event IDs continue to hash that actual workbook ID and the observed worksheet/cell coordinates.
