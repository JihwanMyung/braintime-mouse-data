# Locobox records and reports

Apply `locobox.sql` after `schema.sql`, `export-permissions.sql`, `manager-permissions.sql` and `iacuc.sql`. Existing deployments apply only this additive migration. It adds no source records, permissions, accounts or schedules. Owners/editors can write; managers require Housing; viewers can read. Export authorization remains Low 3 years, High 6 years, Max full history.

`husbandry_events` uses `event_type:locobox_protocol` with a matching `locobox_protocol` object and `schema_version:1`. Its `protocol_id` equals its event ID. The object holds title, status, evidence status, exact cage/position references or an unresolved source label, and 1–100 ordered phases. A confirmed association requires an existing cage in the same colony; an active protocol additionally requires recorded evidence. A position reference alone does not establish a cage's historical exposure.

Each phase has explicit ISO dates, optional `HH:mm[:ss]` clocks, an IANA timezone (the UI defaults to Asia/Taipei), and recorded light parameters. One sequential cage timeline uses one timezone; create a separate record for a timezone change. Clock entries remain recorded wall times, so ambiguous daylight-saving transitions do not establish exact elapsed exposure. End boundaries are exclusive; a date without a clock does not establish an exact transition time. Unknown quantities remain null. DD/LL do not use daily light-on/off clocks. A duration calculated from dates must equal end minus start; a measured CT/ZT phase requires an offset-bearing timestamp and measurement method. Numeric values and dates are validated, but no treatment, exposure, schedule or phase value is inferred by the server.

Treatment records preserve name, planned/administered/cancelled/unknown status, dose and units, concentration and units, route, vehicle, delivery/frequency, and separate dates/clocks. Treatment date bounds cannot extend outside a known phase interval. Blank treatment dates never prove administration. There are at most 100 treatments per phase.

Source observations remain read-only. Existing `source_*` provenance cannot be rewritten, and `locobox_revision` before/after snapshots are append-only. Review creates a separate protocol. Existing version CAS, atomic batch saves and audit history still apply. Typed data disguised under another event type is rejected, including permission checks on both old and new record content.

Report exports inspect each phase rather than accepting the earliest wrapper date as the sole filter. A spanning interval may be included, but dates/clocks outside the requested window and its full duration are withheld. Explicit clipping flags and export-window markers describe the omission without inventing new biological boundaries. An old start with no recorded end is excluded from a bounded report because continuation is unknown. Undated phases/treatments require Max with no lower date bound. Measured-phase dates are evaluated in the phase timezone; treatments receive their own filter. Recorded boundary dates are reportable facts, not an inference of exposure on that day.

Reports omit raw source blocks, notes, schedule narratives and all revision records. Complete preservation backups remain Max-only. Safe arrays carry eligible counts and truncation flags (30 treatments per exported phase, 300 KB of projected phases), keeping pagination finite. CSV/XLSX use `locobox_*` columns and serialize nested phase details; JSON preserves the projected hierarchy. Browser demo projection and SQL report projection are tested together. The general member-readable database still supports ordinary colony work; export levels govern official export/backup workflows, not prevention of manual copying by a member who can read data.

Run `node --no-maglev --test supabase/tests/locobox.test.mjs tests/model-store.test.mjs` for validation, authorization, append-only history, date-window projection and local/SQL parity. These tests use synthetic data and make no live changes.
